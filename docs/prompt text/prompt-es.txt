### **FASE 4: Backend - Capa de Infraestructura**

### **FASE 5: Backend - Capa de Presentación**

### **FASE 6: Backend - Tests (TDD)**

### **FASE 7: Backend - Database & Seed Data**

- `application.yml` con perfiles dev/test
- **Output**: Archivos en `pokeapi/src/main/resources/`

### **FASE 8: Frontend - Setup & Shared Components**
- Configura TypeScript estricto, Tailwind, React Query
- Componentes UI reutilizables (Button, Input, Card, Modal, Toast)
- Layout components (Header, Footer)
- Tipos TypeScript para todas las respuestas de API
- **Output**: Archivos en `pokeui/src/components/` y `pokeui/src/types/`

### **FASE 9: Frontend - Auth Feature**
- Login y Register pages
- Protected route wrapper
- Auth context + hooks (`useAuth`)
- Axios interceptor para JWT
- **Output**: Archivos en `pokeui/src/features/auth/`

### **FASE 10: Frontend - Pokemon Features**
- **Pokemon List**: Grid paginado, cards con sprite/category/mass/skills, skeletons
- **Pokemon Detail**: Hero image, stats, narrative, evolutionary lineage
- **Pokemon Edit**: Form con validación Zod, chips para tags, toasts
- Custom hooks con React Query (`usePokemonList`, `usePokemonDetail`, `useSyncPokemon`, `useUpdatePokemon`)
- **Output**: Archivos en `pokeui/src/features/pokemon-*/`

### **FASE 11: Frontend - Tests**
- Component tests con Jest + React Testing Library
- Tests de hooks con React Hooks Testing Library
- Tests de accesibilidad con jest-axe
- **Output**: Archivos `*.test.tsx` junto a los componentes

### **FASE 12: DevOps & Documentation**
- `Dockerfile` backend (multi-stage: Maven build + JRE 17)
- `Dockerfile` frontend (multi-stage: Node build + Nginx)
- `docker-compose.yml` (postgres + backend + frontend)
- `.env.example` con variables necesarias
- `README.md` completo (setup, API docs, demo credentials, GenAI usage)
- **Output**: Archivos en raíz de `pokeapi/`, `pokeui/` y workspace root

### **FASE 13: Validación Final**
- Ejecuta `./mvnw clean verify` en `pokeapi/` (debe pasar)
- Ejecuta `npm run build && npm test` en `pokeui/` (debe pasar)
- Verifica que `docker-compose up --build` levanta todo correctamente
- **Output**: Reporte de validación con resultados de tests y build

## ⚠️ REGLAS CRÍTICAS (NO NEGOCIABLES)

1. **Clean Architecture Estricta**: La capa `domain/` NO puede importar nada de Spring, JPA, ni frameworks externos. Solo POJOs e interfaces.
2. **TDD**: Escribe tests ANTES de la implementación en cada fase. Si los tests fallan, refactoriza hasta que pasen.
3. **Sin Symlinks**: NO crees enlaces simbólicos en ningún lugar del repositorio (requisito de seguridad del ejercicio).
4. **Manejo de Errores**: Todas las excepciones deben pasar por `GlobalExceptionHandler`. Nunca retornes stack traces al cliente.
5. **Validación Defensiva**: Usa Bean Validation (`@NotBlank`, `@Size`, etc.) + validaciones manuales en servicios.
6. **Caché**: Implementa `@Cacheable` en US01 con TTL de 24 horas (nice-to-have pero evaluado).
7. **JWT**: Tokens en cookies HttpOnly (no en localStorage) por seguridad.
8. **TypeScript Estricto**: `strict: true` en `tsconfig.json`. Sin `any` a menos que sea absolutamente necesario (y documentado).
9. **Responsive**: Mobile-first en el frontend. Prueba en 320px, 768px, 1024px, 1440px.
10. **Seed Data**: La app debe funcionar out-of-the-box con datos de demostración.

## 📊 CRITERIOS DE ÉXITO

Al finalizar, el proyecto debe cumplir:
- ✅ Las 4 User Stories funcionan end-to-end
- ✅ Cobertura de tests ≥ 80% en backend
- ✅ `docker-compose up` levanta todo sin errores
- ✅ Frontend responsive y accesible (WCAG 2.1 AA)
- ✅ Clean Architecture verificable (capas independientes)
- ✅ No warnings en consola del navegador
- ✅ README completo y preciso
